## 0. 摘要

六个页面是工作台工具面板，共用最大 920px 的右侧抽屉、一条标签栏和一个滚动容器。目标是让用户看清对象、操作和保存范围；常用操作在长列表中可达；切换页面不会无声丢失未提交内容。视觉一致性不要求六页拥有完全相同的工具或业务状态。

**诊断**：已有 `WorkspaceFrame`、`PageHeader`、共享控件与 CSS；缺口是页面操作位置、保存范围说明、错误反馈和切页生命周期不统一。断点不同、嵌套 tabpanel 和页内不同容器本身不是缺陷，需证明它们造成了实际溢出、不可达或语义歧义。

**三条主张**：

1. **复用现有骨架，保留业务差异**。页面头部 + 按需工具条 + 内容 + 可换行说明；三种布局模式是设计约定，不是新增三个组件或合并六页的理由。
2. **保存与筛选一起可达**。长列表采用一处 sticky 操作区，包含配置保存、校验和就地反馈；保存不留在滚出视野的页面头部。资源页只在确有长列表操作需求时吸顶。
3. **区分浏览状态、业务草稿和危险瞬态**。搜索/展开可保留；草稿按实际 owner 与身份保留；导入确认、删除确认、拖拽和创建意图仍按原边界失效。切页滚动与焦点必须一起验收。

## 1. 六个页面的功能定位

判断一个页面的设计对不对，先看它要让用户完成什么。以下是六个页面的产品职责（依据 `workspace-pages.ts:9-51` 的页面定义与各页实现）；“频次”是待用户使用验证的设计假设，不是遥测结论：

| 页面 | 用户的动词 | 对象 | 频次 | 页面性质 |
|---|---|---|---|---|
| **主会话** | 编排 / 启停 / 排序 | 提示词配置、引擎能力、自定义工具、人设 | 最高 | 配置工作台（写密集） |
| **子代理** | 编排（受众=子代理） | 子代理可见配置、能力、模型与委派策略；无指令文件卡 | 中 | 配置工作台（受众视角） |
| **工具预览** | 查看 / 核对 | 当前会话与所选预设的模型工具面 | 低 | 只读诊断 |
| **技能设置** | 引入 / 排序 / 启停 | 技能目录、技能、排序基数 | 中 | 资源库（写中等） |
| **预设配置** | 切换 / 新建 / 导入导出 | 预设、写入开关与生成顺序 | 中低 | 资源库（写中等） |
| **角色管理** | 导入 / 应用 / 移除 | 角色卡（PNG / JSON） | 低 | 资源库（导入密集） |

**关键观察**：主会话与子代理共享预设及提示词配置的受众视角，但页面并不等价。除子代理排除 `tool-filter` 外，主会话独占指令文件卡；模型路由、人设、委派与工具策略也有各自 owner。指令文件正文及策略独立于预设（ADR-0003），不能为统一页面而并入 `preset.yml` 或复制到两个入口。

两页使用相同的视觉节奏和操作位置，继续复用 `PromptConfigList` 等既有组件，保留独立页面编排。页面中的插入点展示顺序只帮助阅读，不暗示全局运行顺序（ADR-0002）。

## 2. 页面级现状诊断

### 2.1 问题清单（均带证据）

#### 问题 1：共享外壳已有，页面内部操作位置不一致

六页的内容区结构各不相同：

| 页面 | 首屏第一个元素 | 工具条位置 | 内容容器 |
|---|---|---|---|
| 主会话 | 公共配置卡区（`PromptConfigsEditor.tsx:149`） | `sectionHeading` 右侧（`PromptConfigList.tsx:269`） | `configList` |
| 子代理 | 模型 / 委派工具卡（`SubagentPage.tsx:74-79`） | 同上（经 `toolbarActions`） | `configList` |
| 技能设置 | 状态统计标签栏（`SkillsPage.tsx:219-246`） | `listFilterRow`（`:351`） | `skillCardList` |
| 预设配置 | 写入预设开关（`PresetsPage.tsx:21-25`） | `PresetSwitcher` 内部 | `presetGrid` |
| 角色管理 | 有待确认导入时为预览卡，否则为操作条（`CharactersPage.tsx:179-220`） | `settingRowStack` 内 `inlineControls`（`:197`） | `presetGrid` |
| 工具预览 | 搜索框（`ToolsPreviewPage.tsx:39-43`） | `toolSurfaceControls`（`:50`） | 分组折叠 |

同一类操作（刷新、导入、新建、批量）出现在**五种不同容器**中。

#### 问题 2：页面纵向节奏来自三种机制

| 页面 | 分区间距来源 |
|---|---|
| 主会话 | `page` gap 28px（`prompts.module.css:7`）+ `section` gap 12px（`controls.module.css:62`）+ `commonCards` gap 10px（`prompts.module.css:126`）——**三层容器各有一套 gap** |
| 子代理 | `section` gap 12px + `subagentConfigs` 的 `margin-top: 12px`（`controls.module.css:67`） |
| 技能 / 预设 / 角色 | 单一 `section` gap 12px，靠 `rowGroup` 的 `border-bottom` 分组（`controls.module.css:367`） |

后果：同样的"两个区块之间"在不同页面视觉权重不同，用户无法形成稳定的空间预期。

#### 问题 3：工具栏在长列表中需滚回顶部

`canvas` 是唯一滚动容器（`PromptWorkspace.module.css:208-217`），工具条位于文档流顶部。配置列表可达 129 张卡（`PromptConfigCard.tsx:18` 注释明确提到"129 卡列表"），技能列表同样可能很长。

用户在列表中部想**保存**（`PromptConfigList.tsx:273`）、**校验**（`:272`）或**换筛选**（`:316-327`），必须手动滚回顶部。工具栏没有任何吸附行为。

#### 问题 4：切页会卸载局部状态，不能笼统提升所有状态

`WorkspaceFrame.tsx:65` 对非活动页面使用条件渲染 `{active && (<>…</>)}`，即**卸载**非活动页面的组件树。以下浏览/交互状态是组件内 `useState`：

- 技能页：`skillFilter`、`statusTab`、`selected`（浏览上下文）；`dragFolder`、`dropTarget`、删除确认（应清理的瞬态）（`SkillsPage.tsx:37-42`）
- 主会话页：`viewFilter`、`variablesExpanded`、`toolCreate`（`MainSessionPage.tsx:22-29`）
- 预设/角色页：各自局部状态

后果：在技能页筛选到"停用"、勾选 5 个技能，切到预设页再切回——筛选与勾选全部清空。129 张卡的列表里重新筛一次是实际成本。

`docs/ui-architecture.md` 的现行契约是 feature 局部生命周期。本文仅建议将明确列出的浏览状态提升到工作台实例期，属于待实施的契约调整。`CustomToolsCard.tsx:26`、`CustomToolEditor.tsx:80` 的工具与原始 JSON 草稿仍在组件内；“业务草稿全部已由 store 保护”不成立。不能靠把六页全部保持挂载解决问题，否则会改变导入卸载清理与工具预览按需请求。完整边界见 6.3。

#### 问题 5：切页继承旧页面的滚动位置

`canvas` 单一滚动容器 + 六页共用，切页时 `scrollTop` 不变；`PromptWorkspace.tsx:28` 只有 `const [page, setPage] = useState(...)`，没有任何滚动副作用。

风险：在长页面滚到底部后切到短页面，旧 `scrollTop` 可能保留或被浏览器夹取到新页面底部，使头部不在视野；具体偏移需浏览器复现，源码只能证明没有显式恢复策略。

#### 问题 6：页面标题层级并列

页面头部标题是 `<h2>`（`controls.module.css:24-34` 作用于 `.pageHeader h1, .pageHeader h2`，`WorkspaceFrame.tsx:14` 用 `<h2>`）；主会话列表的分区标题**也是** `<h2>`（`PromptConfigList.tsx:268`）。

同一页面出现两个并列的 `<h2>`，而实际语义是"页面 → 分区"的嵌套关系，应为 `h2` → `h3`。技能页的状态标签栏、目录折叠卡又有各自的标题层，整体没有稳定的层级。

#### 问题 7：空状态四形态，且多数没有下一步

| 页面 | 空状态形态 | 空态区域是否有就近操作 |
|---|---|---|
| 主会话 / 子代理 | `emptyState` 大卡 + glyph（`controls.module.css:842-869`） | ❌ 只有标题与说明 |
| 技能 | 同款大卡（`SkillsPage.tsx:378`） | ❌ |
| 角色 | 同款大卡（`CharactersPage.tsx:223-229`） | ❌ |
| 工具预览 | 纯文本 hint（`ToolsPreviewPage.tsx:54`） | ❌ |
| 预设 | 由 `PresetSwitcher` 内部决定 | — |
| 列表筛选无结果 | `readOnly` 一行文本（`PromptConfigList.tsx:352`、`:360`） | ❌ |

baseline-ui 要求空态有明确下一步。这里的缺口是空态区域缺少就近引导；现有页面工具条已有创建或导入入口，不能据此断言整页没有操作。下一步须由真实原因决定：无对象可创建，筛选无匹配可清除筛选，加载失败可重试，只读则解释并引导选择可编辑预设。

#### 问题 8：插入点与内容策略共用单选视图，标签需讲清范围

主会话下拉同时列出“全部 / 世界书 / 各插入点”（`PromptConfigList.tsx:320-324`）。“全部”是不施加视图限制，“世界书”是内容策略，其余是插入点。现有单选模式不表达交集；本轮不新增组合筛选。下拉分组只帮助理解，不声称支持多维筛选。

（这是产品语义问题在 UI 上的暴露。本文不改变筛选语义，只提出呈现建议：分组标题区分两个维度——`MenuSelect` 已支持 `group`，见 `MenuSelect.tsx:33-36`。）

#### 问题 9：断点分属不同尺寸对象，不能直接合并

| 阈值 | 位置 | 类型 |
|---|---|---|
| 520px | `PromptWorkspace.module.css:262` | 视口 |
| 620px | `controls.module.css:1030`、`prompts.module.css:107`、`:128` | 视口 |
| 640px | `prompts.module.css:81` | 容器 |
| 720px | `prompts.module.css:96` | 视口 |
| 760px | `PromptWorkspace.module.css:254` | 视口 |
| 960px | `prompts.module.css:85` | 容器 |

抽屉宽度为 `min(920px, 100vw)`（`Workbench.module.css:5`）；页面 padding、卡片边框和列宽会继续减少内容宽度，因此视口、页面容器与卡片容器从来不是同一测量对象。宽视口下，卡片的 960px 容器条件可能无法触达。是否溢出需按真实内容宽度验证，不能断言所有已有阈值错误；本轮不附带放宽抽屉。

#### 问题 10：嵌套 tabpanel

技能页内部有 `role="tablist"`（状态筛选，`SkillsPage.tsx:220`）与 `role="tabpanel" id="pt-skills-panel"`（`:372-376`），而外层 `WorkspaceFrame.tsx:60-61` 已经把整个页面包在 `role="tabpanel"` 里。

嵌套 tabpanel 本身合法，不是无障碍错误。内层确实用于列表过滤，可改为命名的按钮组：原生 button + `aria-pressed`，始终只有一个选中，全部按钮按普通 Tab 顺序可达，不继承旧 tab 的 roving tabindex/方向键逻辑。同时移除该筛选区域的 `role="tab"`、`tabpanel` 与旧关联属性。外层六页 tablist 保持原契约。

## 3. 页面骨架设计

### 3.1 统一骨架

```
┌ WorkspaceFrame / PageHeader（复用现有外壳）─────────────────────┐
│                                                                  │
│  页面头部                                                        │
│  标题 (h2) + 一句话说明 + 数量 / 当前预设                         │
│                                                                  │
├─ 操作区（长列表 sticky，按页面提供已有操作）─────────────────────┤
│  [搜索] [视图▾]   [批量…] [校验] [创建 ▾] [保存配置]            │
│  与该操作关联的保存中 / 失败 / 部分成功反馈，可换行               │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  内容区（三种模式之一）                                          │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│  页脚说明（可选，允许换行）                                       │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 页面头部与主要动作

| 元素 | 规格 | 说明 |
|---|---|---|
| 标题 | `h2`，16px / 600 / `--dsw-alias-label-primary` | 来自现有 `PageHeader`（`WorkspaceFrame.tsx:11-18`），字号由 17px 收敛到官方 `--dsw-font-base-16` |
| 说明 | 13px，`max-width: 64ch`，允许换行 | 现有 `.pageHeader p` 保持；必要说明需满足普通文字 4.5:1 对比度，三级色不合格时提升到可读 token |
| 统计元信息 | 现有统计胶囊（`PromptWorkspace.module.css:240-252`） | 中性色、数字 `tabular-nums`；自然语言统计用普通文本语义，三级色须通过对比度验证 |
| **主操作** | 优先现有宿主 Button，一处主要强调 | 放页面操作区，不在非 sticky 头部复制第二个保存按钮；组件 API 以已安装包类型为准 |

各页的主操作（每页至多一个）：

| 页面 | 主操作 | 依据 |
|---|---|---|
| 主会话 / 子代理 | 保存配置（复用现有 `PromptConfigList` 保存回调） | 手动校验及保存配置，并按现有主会话回调处理 dirty 指令文件；不承诺保存所有 feature 草稿 |
| 预设配置 | 新建预设 | 资源库的创建入口 |
| 角色管理 | 导入角色卡 | 该页的主要任务 |
| 技能设置 | 无（资源已存在，"添加目录"降为工具条操作） | 高频操作是启停与排序，不是添加 |
| 工具预览 | 无（只读页面） | — |

### 3.3 操作区（优先共享样式）

先在 `WorkspaceFrame` 与现有 feature 中统一位置和 CSS；操作回调留在原 owner。不为排版创建新的 store、Context 或通用 `PageShell`。只有至少两处真正重复同一结构时，才提取只接收内容槽的薄组件；不要求主会话与子代理合并。

| 项 | 规格 |
|---|---|
| 高度 | 桌面 `min-height: 48px`，允许自然增高，不能固定高度裁切换行 |
| 内边距 | 页面 16px、窄容器 12px；操作区与内容起点对齐，不再叠一层 padding |
| 搜索框 | 理想宽度 240–320px，标准高度 32px；`min-inline-size: 0`、可缩，窄容器占满一行；沿用原生 search 与可访问名称 |
| 筛选 / 视图选择器 | 官方 `Menu`（经现有 `MenuSelect`），标准 36px、紧凑 28px；输入紧凑 28px，不能误把所有标准控件定成同一高度 |
| 批量操作 | 技能按选中项操作，显示目标数量；配置按筛选后可见配置操作，明确标注可见数量，两者不强行统一 |
| 分隔 | 底部 `0.5px solid var(--dsw-alias-border-l2)` |
| **吸顶** | `position: sticky; inset-block-start: 0`，只相对现有 canvas；背景不透明，使用命名的局部 sticky 层级，低于菜单与弹窗 |

吸顶约束：

1. 吸顶元素必须有**不透明背景**，否则滚动内容会从下方透出（`bg-base` 在亮色与暗色下都是页面的底色，`design-platform.css:157`、`:252`）。
2. 保存、校验及其反馈都处于这一区域；只吸顶搜索却把保存放在上方头部不能解决问题 3。
3. 工具条会因窄宽度、200% 文本缩放、英文和错误文本换行，不能写死 `scroll-margin-top: 56px`。为操作区注册一个 `ResizeObserver`，仅在尺寸变化时更新实际遮挡高度，canvas 的 `scroll-padding-block-start` 用该高度；目标可另加 8px 间隙，避免同一高度计算两次。创建定位与 Tab 聚焦都必须验证可见，测量/写入不交错、不在滚动时反复读布局。
4. sticky 元素的包含块必须覆盖对应列表，不能嵌在仅包住头部的短容器；不增加页面级内层 `overflow: auto`，不对列表祖先加会裁切菜单的 overflow。
5. 屏幕可用高度过小时，工具条退回普通文档流，避免挡住大部分编辑区；以焦点和软键盘可见性验证，暂不规定未经实测的高度阈值。菜单/弹窗沿现有 portal owner 管理，Escape 只关闭当前最上层。

### 3.4 内容区与页脚

- 内容区沿用页面现有容器（`configList` / `presetGrid` / `skillCardList`）：模块卡列表保留 10px，资源网格 12px；卡头与卡内 padding 以模块卡稿为准，不在本文重复定义。
- 页脚说明按现有文字 token 排版，允许中文/英文自然换行，必要信息不截断；**去掉 `margin: -14px 0 0` 这类负外边距**，由所在布局的 gap 表达距离（`prompts.module.css:123`）。

## 4. 三种页面布局模式

### 模式 A：配置工作台（主会话、子代理）

**特征**：写密集、卡片可展开编辑、需要保存与校验、列表长。

```
页面头部（标题 + 说明 + 当前预设）
操作区（搜索 | 插入点/策略视图 | [批量启停] | [校验] | [创建 ▾] | [保存配置]）
操作反馈（与上方一起 sticky；保留字段级错误）
公共区（模型卡 · 提示词默认值卡 · 模板变量卡）
────────── 0.5px 分隔线 ──────────
置顶卡（人设卡；世界书视图下显示诊断卡）
能力/工具卡区
层级配置卡列表
页脚说明
```

设计要点：

1. 公共区与具体条目之间用已有边框或间距表达分组，只保留一处分界，不叠加装饰。公共区含当前会话模型与预设变量等不同 owner，不能统一标成“全局配置”。
2. **创建菜单（`EngineModuleActions`）从 `sectionHeading` 移到工具条**，与筛选、批量操作在同一区域，窄空间自然换行。
3. **保存留在 sticky 操作区**。操作区说明保存范围；自定义工具、人设、参数、子代理策略继续走既有保存通道。当前配置还会 debounce 自动保存，不能把手动按钮表现为唯一写盘入口；保存中只禁用冲突动作，后续输入保持草稿，不能提前显示全部已保存。
4. **两页共享布局纪律，保留各自组合文件**。主会话拥有指令文件卡，子代理拥有委派与策略入口；`scope`、受众、只读与排除能力继续由原组件处理。仅复用真正相同的结构，不以假想第三类页面为理由建立参数化框架。
5. 筛选只影响展示。新建不改搜索词和视图；目标被筛掉时保留筛选并给“显示全部”的显式操作。不要自动清筛选，也不要把能力/工具纳入提示词搜索与批量作用范围。

### 模式 B：资源库（技能设置、预设配置、角色管理）

**特征**：对象数量中等、以卡片网格或行列表呈现、操作为"引入 / 状态切换 / 排序 / 删除"。

```
页面头部（标题 + 说明）
操作区（各页已有主操作；技能保留搜索/筛选/当前结果全选）
导入预览（预设包 / 角色卡 JSON，保留现有确认流程）
内容区：
  ├ 行列表（技能：带层级缩进、拖拽手柄、开关）
  └ 卡片网格（预设、角色：按真实内容宽度自动容纳）
页脚说明
```

设计要点：

1. 状态筛选可采用有名称的普通按钮组，说明这是同一列表的过滤；计数表明是整个目录总数还是当前匹配数，避免两套含义混用。
2. **本轮保留技能批量按钮固定位置**：无选中时禁用并显示“先选择技能”；选中后显示“已选 N”。避免按钮出现/消失移动正在操作的焦点。配置列表没有同款勾选模型，保留“启用/停用可见 N 项”的语义。
3. 技能目录仍是列表前的折叠管理区，默认收起；工具条“目录”按钮可展开并定位。初次没有技能或目录失效时显示直接操作入口。不要把路径输入、目录排序等表单塞进 Menu，也不要沉到长列表末尾。
4. **角色卡网格复用预设卡形态**（当前已复用 `presetGrid` / `presetCard`，`CharactersPage.tsx:231-235`）——这是正确的复用，保持。

### 模式 C：只读诊断（工具预览）

**特征**：只读、两组数据（当前会话 / 所选预设）、需要搜索与分组。

```
页面头部（标题 + 说明）
工具条（统一搜索）
分组 1：当前会话（可折叠；自己的刷新/加载/错误/空态）
分组 2：所选预设（可折叠；唯一来源选择器、预设目录刷新与工具面刷新）
页脚说明
```

设计要点：

1. 两个 `ToolSurfaceView` 已有折叠与独立刷新，继续复用。预设来源选择只放在其分组标题处，不在工具条重复一份。
2. 保留独立“工具预览”顶层页，仅显式打开时请求。说明当前会话读取已冻结 generation，所选预设展示后续 generation；不显示虚构“运行中/已启用”，不为填空自动创建会话。
3. 搜索为客户端过滤。会话工具面、预设目录和所选预设工具面各自拥有加载、失败与重试，错误贴近对应组，不合并成一条全页告警而遮盖另一组成功数据；切来源后的旧响应继续作废。

## 6. 页面间导航与关系

### 6.1 保留六页与单一标签栏

`features → subagent → tools → skills → presets → characters` 的 ID、顺序与入口保持不变（`workspace-pages.ts`、`docs/ui-architecture.md`）。只有一个 tablist，保留自动激活、roving tabindex、左右循环、Home/End、稳定 tab/panel 关联。不能因“只读”降低工具预览可发现性，也不分成两套方向键组。窄屏允许标签栏独立横向滚动，活动 tab 可见；正文不得横向溢出。

### 6.2 跨页跳转

跨页捷径只服务于具体任务，不建立路由库或让 `ui/` 读取 store。需要时由 `PromptWorkspace` 提供窄 `onNavigate(page)` 回调给相关页面：

| 场景 | 应有跳转 |
|---|---|
| 有可编辑预设但当前配置为空 | 就地「创建第一条配置」，不要求另建预设 |
| 没有预设 / 当前预设只读 | 「选择或新建可编辑预设」→ presets |
| 角色卡“应用到当前预设”成功后 | 可选「查看新增配置」→ features；不自动切页、不自动清筛选 |
| 技能页无目录 | 「添加技能目录」→ 就地展开目录区 |
| 工具预览无预设来源 | 预设分组内刷新目录，确无预设时才提供 → presets |
| 当前会话不存在 | 解释“需要当前会话”；只有已有宿主入口时提供返回对话，不自动创建会话 |

键盘切 tab 后焦点留在新的 tab，内容通过现有 panel 的 Tab 顺序进入；不能每次自动聚焦标题打断方向键。用户点击内容中的跨页动作后，待目标挂载，把焦点置于目标标题/指定入口（必要时 `tabIndex=-1`）。焦点交接与滚动恢复由同一导航 owner 协调，使用 `preventScroll` 防止两次跳动。异步刷新不得抢焦点。

### 6.3 状态归属（修订）

| 状态 | 目标生命周期与身份 | 退出/变化行为 |
|---|---|---|
| 当前页面 | `PromptWorkspace` 实例期；不写 URL/localStorage | 保持现有抽屉开关行为 |
| 搜索、视图、展开 | 工作台内按页面存纯数据；预设相关展开再按 presetId | 回到同页同预设恢复；删除实体后清理失效 ID |
| 技能选中项 | 当前技能目录 + 当前筛选结果 | 恢复时重算合法集合；目录/筛选变化按 5.4 收紧 |
| 页滚动 | 按 pageId + 必要 presetId 记录 | 初访为 0；列表与展开布局就绪后一次恢复并夹取范围；异步后续刷新不反复抢滚动 |
| store 中的预设草稿/队列 | 现有 store + presetId / snapshot | 保留保存版本保护、预设事务和失败输入；不复制到浏览状态 |
| 指令文件正文草稿 | 现有独立草稿池 + contextId / fileId / version | 切页不清除；上下文变化按白名单和版本契约；与预设保存分离 |
| feature 局部业务草稿 | 工具、人设、策略各自 owner；保存原始文本与校验错误 | 待实现：最小提升至稳定 owner，切页再回输入不丢；不能只保留解析成功的 JSON，也不能用组件常驻绕过清理 |
| 导入预览、删除确认、拖拽、创建意图 | 原 feature 局部生命周期 | 切页关闭/作废；回页不恢复危险动作、不重放请求；已发往服务端的写入不可假称已撤销 |

不新增状态库，不用 localStorage 储存内容。按页面显式定义需要保留的少量字段，不建立任意状态容器。滚动最小修复可以先做“切页归零”，但必须标为阶段结果；它不能代替保留浏览上下文的最终验收。

草稿保护是单独的实施任务：先逐一确认真实 owner 和提交触发点，再调整生命周期。菜单/弹窗 portal 的焦点转移不等同于离开业务编辑器，不得借卡片 blur 清空未保存内容。切换预设时，各局部草稿需明确保存、阻止切换或显式放弃流程，不能声称 store 的切换事务已覆盖所有 feature；新会话/工作区不得重放旧身份写入。

## 7. 状态与空态规范

### 7.1 状态按实际请求 owner 呈现

| 状态 | 呈现 | 位置 |
|---|---|---|
| 加载（无数据） | 骨架，**形状匹配该页真实结构**（配置页=卡片行、资源页=网格块）；`aria-busy` | 内容区 |
| 加载（同一来源已有数据） | 保留数据 + “正在刷新”文字/局部 spinner；旧数据明确标记 | 对应工具条或分组；切换来源时不把上一来源冒充当前数据 |
| 空 | 图标 + 标题 + 一句说明 + 一个有效下一步 | 内容区；若无安全动作则解释条件，不造假按钮 |
| 筛选后无结果 | 简短可换行文本 + 「清除筛选」 | 内容区（区别于真空态） |
| 错误 | 操作级错误贴近动作，可换行、可重试；字段错误用 `aria-invalid` / `aria-describedby` | 保存区、对应分组或字段 |
| 只读 / 写入不可用 | 显示 system、关闭写入或加载失败等具体原因 | 受影响区域附近；不能仅把按钮变灰 |

当前骨架是固定 4 行等宽条（`WorkspaceFrame.tsx:69-71`）。先修正 `hasData` 的 owner：全局存在 promptConfigs 不代表角色库已加载，加载失败也不是空库。初次无数据用接近内容形状的静态占位和 `aria-busy`；骨架本身 `aria-hidden`，区域仅播报一次加载状态，不必为六页各造一个 skeleton 组件。

### 7.2 空状态统一形态

```
        [图标 42px]
        这里还没有提示词配置          ← h3，沿用16px标题角色
        提示词配置决定什么内容、在什么时机注入到会话。  ← 12px说明角色，普通文字对比≥4.5:1，max-width 60ch
        [ 创建第一条配置 ]            ← 主操作，至多 1 个
```

改造要点：补就近操作，去装饰性渐变/光晕，图标 `aria-hidden` 且不加动画；不显示“没有配置”来替代“搜索无匹配”“加载失败”或“只读”。配置创建沿用统一创建入口；空态的快捷按钮调用同一个动作。

### 7.3 notice 与页内错误的区别

现有全局 `notice` 渲染在内容区**底部**（`WorkspaceFrame.tsx:73`），而保存/校验的反馈来自列表工具栏（`PromptConfigList.tsx:144`、`:272-273`）。

长列表下，保存按钮与底部反馈相隔很远，用户触发保存后可能看不到结果；把操作区吸顶后仍需同时解决反馈位置。

建议：保存/校验反馈贴近操作区，正常状态 `role="status"` / polite；阻断当前动作的新增错误才使用告警，避免每次重渲染重复朗读。只有一个 live owner，不在底部再朗读同一条 notice。失败信息持续到重试成功或用户处理，不能仅依赖会消失的 toast。跨页返回时可见的错误须关联原对象，不能伪装成当前新预设的失败。

### 7.4 导入确认与危险操作不得回退

预设包与角色卡 JSON 继续复用 `ImportPreviewCard` + `useImportPreviewFlow`。页面重排遵循现有行为：

| 阶段 / 事件 | 必须保留的行为 |
|---|---|
| reading / 换顺序组重预览 | 确认不可用，显示正在处理；不把旧报告当成可提交的新报告；取消结束当前单元，迟到结果无效 |
| 顺序组候选 | 仅选组，不能确认写入；选择/改选都重新预览 |
| confirming 且报告 ready | 确认、取消可操作和键盘聚焦，不能因“导入中”整卡禁用 |
| submitting | 防连点且最多一次提交；显示提交中，不能宣称取消可撤销已发出的写入 |
| 普通提交失败 | 保留原文件、选择与报告供再次确认重试；错误贴近确认区 |
| sourceDigest / previewRevision 过期 | 旧确认失效，要求重新导入/预览，不能重试旧凭据绕过校验 |
| 切页 / 卸载 / 目标变化 | 结束等待，迟到响应不覆盖新上下文，不继续写下一个文件；不把流程存进浏览状态 |
| 报告内容 | 完整 warning / info / 排除条目可读且可定位；不得恢复 20 条截断，滚动区域有名称且键盘可达 |

阅读预览时不抢到“确认”并自动提交。取消/完成后回到相应导入入口；入口因切页已消失则由导航 owner 落到目标 tab/标题，不把焦点恢复到已卸载节点。PNG 路径沿现有上传语义，不为统一外观假设它与 JSON 转换报告相同。

物理删除预设/角色库文件须明确对象和后果，使用现有 `DialogSurface`/官方能力提供 alertdialog 等价确认：有名称与描述、取消优先、焦点限制和关闭恢复；确认中防重复请求，失败保留对象及可重试信息。可逆的移除应用仍沿原 feature 的局部确认，不把所有开关都升级为模态弹窗。是否能提供某个角色/prop 必须核对已安装 primitive，不能仅补 ARIA 标签假称完整行为。

## 8. 响应式与断点

### 8.1 按内容容量响应，不强行统一所有数字

保留现有各 owner 的 520/620/640/720/760/960 条件作为审查起点；字段网格、导航、页面操作区测量不同，不要求使用两条全站断点。只有实际内容宽度支持更多列才增加列数，不因视口达到 960px 就让 920px 抽屉显示三列。

卡片最小理想宽度可先沿用 268px，使用原生 grid 自适应，例如 `repeat(auto-fit, minmax(min(100%, 268px), 1fr))`；小于最小宽度时仍收缩为一列。页内操作区使用 flex-wrap，允许英文和数量文本换行。新值是待浏览器核验的候选，不能在未渲染前声称最优。

### 8.2 容器查询优先

字段网格已经用容器查询（`prompts.module.css:31-33` 的 `container-type: inline-size` + `:81`、`:85`）。**页面级断点也应改用容器查询**，因为工作台的实际可用宽度是抽屉宽度（`min(920px, 100vw)`，`Workbench.module.css:5`），而不是视口宽度。

页面查询容器与卡片查询容器分别命名，避免嵌套时误读最近容器。查询声明放在被调整内容的祖先，不能靠元素查询自身宽度改变自身布局。保留现有抽屉宽度，先扣除 padding/gap 后再验证列表容纳能力。

若需旧环境兜底，使用 `@supports not (container-type: inline-size)` 隔离视口规则，避免容器规则与视口规则同时覆盖。安全区与抽屉高度归工作台壳负责；本页不叠加 `100vh` 或第二个滚动根。

### 8.3 需要观察的行为

| 实际可用空间 | 操作区 | 内容 |
|---|---|---|
| 能容纳全部控件 | 优先一行，不用强制 nowrap | grid 自适应列数；字段按卡片容器规则 |
| 控件开始拥挤 | 搜索可占一行，其余自然折行；不限制只能两行 | 长路径省略并提供完整可读值，提示和错误换行 |
| 320px CSS 宽或 200% 文本缩放 | 保存/取消/刷新仍可达；目标至少 24×24 CSS px，不依赖间距例外，触控优先 44×44 | 单列、无正文横向滚动，文字无裁切 |
| 可视高度不足 / 软键盘展开 | 必要时解除 sticky，焦点保持可见 | 编辑区仍能滚到末尾，safe-area 不遮挡操作 |

明暗主题均验普通文字 4.5:1、必要图标/边界与焦点提示 3:1；禁用原因不用颜色单独表达。默认不增加入场、切页或滚动动画，现有动效在 reduced-motion 下关闭非必要移动。
