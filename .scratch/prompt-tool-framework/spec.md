# 如何验收 Prompt Tool 框架

本规格定义 Prompt Tool 框架的可观察行为和交付标准。它覆盖 DeepSeek Harness（DSH）的预设、提示词注入、工作台、运行时引擎（Engine）、子代理、SillyTavern 转换与持久化边界。

## 文档计划

这份 Reference 文档帮助维护者和实现代理判断框架是否符合已确立契约。文档计划如下：

- **目标**：验收框架的用户流程、交互契约、存储语义、运行时行为和安全边界
- **读者**：熟悉 DSH 预设和 Cordis 生命周期的项目维护者与实现代理
- **前置知识**：DSH 会话、预设发现、工具调用和子代理的基本概念
- **内容**：问题、解决方案、用户故事、框架要求、测试决策、非目标和已知缺口
- **开放问题**：无；本规格将现有硬约束和已接受架构决策记录视为已决定

## 问题陈述

框架契约分散在用户界面（UI）、参数、Engine 和 SillyTavern 文档中。这些文档同时包含当前决策、实现细节和历史结论。

维护者因此缺少一份可以直接验收的当前态规格。单个模块测试通过时，跨层行为仍可能偏离预设隔离、保存一致性、注入语义或宿主边界。

## 解决方案

建立一份按用户可观察行为组织的框架规格。每项框架要求都有稳定标识符（ID），高风险流程通过验收面追踪到现有测试。

本规格沿用 [领域词汇](../../CONTEXT.md)。它将两份架构决策记录（ADR）视为已决定：[预设定义是行为配置的唯一来源](../../docs/adr/0001-preset-definition-is-authoritative.md) 和 [官方插入点保持彼此独立](../../docs/adr/0002-insertion-points-remain-independent.md)。

## 用户故事

用户故事从预设使用、配置编辑、运行时注入、资产转换和框架维护五条旅程覆盖预期行为：

### 选择与物化预设

1. 作为预设使用者，我希望切换预设后恢复其完整行为，从而避免其他预设的值泄漏进来。
2. 作为预设作者，我希望在单一可写定义中编辑行为，从而保留注释、未知字段和预设隔离。
3. 作为预设作者，我希望显式装配能力模块或使用空组合，从而不会因残留参数启用功能。
4. 作为预设使用者，我希望导入、复制、切换和重建失败时保留可恢复状态，从而不会得到半成品。

### 编辑提示词与配置值

5. 作为工作台用户，我希望新建、编辑、校验、排序和放弃提示词配置，从而不用改动 Engine。
6. 作为工作台用户，我希望保存严格串行且不覆盖较新草稿，从而保持未保存（`dirty`）状态准确。
7. 作为预设作者，我希望空预设参数回落上层默认，但 `0`、`false` 和空模板变量保留，从而区分回落与显式值。
8. 作为工作台用户，我希望留空模型路由时继承宿主默认，从而不会意外锁定 `provider`。

### 运行提示词与工具

9. 作为主会话用户，我希望提示词只在声明的插入点、时机、消息受众和模型范围生效，从而获得可预测的会话行为。
10. 作为主会话用户，我希望首轮锚定、每轮引导和兜底注入保持独立，从而可以分别选用。
11. 作为主会话用户，我希望晋升状态从持久事件恢复，并在新 epoch 重新判定，从而让恢复、重载与在线运行一致。
12. 作为预设作者，我希望渐进披露和 Programmatic Tool Calling（PTC）呈现保持 opt-in，从而按需组合工具体验。
13. 作为工具使用者，我希望自定义工具经过参数校验、审批和官方调度，从而不会执行未授权请求。

### 使用工作台与子代理

14. 作为工作台用户，我希望从宿主官方 `slot` 进入固定五页，从而按任务找到对应编辑面。
15. 作为键盘或屏幕阅读器用户，我希望获得完整的导航、焦点、状态和错误反馈，从而不依赖指针或视觉线索。
16. 作为工作台用户，我希望首屏读取、延迟数据和草稿刷新互不阻塞，从而持续编辑。
17. 作为子代理管理者，我希望预览并冻结授权上限内的工具集，从而避免运行中扩权。
18. 作为技能管理者，我希望区分目录引用与文件夹导入，并筛选、排序、启停、修复和重扫技能，从而维护有效技能目录。

### 转换 SillyTavern 资产

19. 作为 SillyTavern 预设使用者，我希望保留内容、启停、角色和顺序，但不覆盖 DSH 采样设置，从而继续编辑转换后的预设。
20. 作为角色卡用户，我希望将 Portable Network Graphics（PNG）或 JavaScript Object Notation（JSON）资产导入角色卡库，再幂等地应用或移除，从而跨预设复用角色。
21. 作为世界书用户，我希望常驻、关键词、正则和选择逻辑产生确定性注入，从而只获得当前需要的上下文。
22. 作为角色卡用户，我希望模板变量、会话变量和角色记忆保持不同生命周期，从而区分默认值、临时状态与长期上下文。

### 维护框架边界

23. 作为框架维护者，我希望 `host`、`client` 和 Engine 共用 `bridge` 契约，从而在落盘前拒绝非法请求。
24. 作为框架维护者，我希望物化与重挂保持原子性和唯一活跃实例，从而不会损坏当前会话。
25. 作为框架维护者，我希望新参数、端点和能力在所有消费端受契约测试约束，从而在交付前发现漂移。

## 框架要求

以下要求定义可观察行为和硬边界，不固定内部函数、缓存键或组件名：

### 预设权威与组合

预设定义是唯一可写行为源，生成目录只是可替换物化结果：

- **R-PRESET-01**：每个预设隔离保存预设参数、提示词配置、模板变量、模型路由、能力模块和子代理工具策略
- **R-PRESET-02**：全局 `settings` 只保存部署设置；大文本、原始资产和秘密使用文件或回环数据通道（loopback bridge）
- **R-PRESET-03**：能力模块只在 `modules` 显式声明时装配；空声明产生合法空组合
- **R-PRESET-04**：预设参数覆盖行级 `moduleConfigs`，行级配置再覆盖组合默认
- **R-PRESET-05**：残留预设参数和 dormant `moduleConfigs` 不得隐式启用能力模块
- **R-PRESET-06**：本地自有组合与官方生成组合分开管理；同名模块和同一预设中的重复 `row` 直接失败
- **R-PRESET-07**：旧组合名称只在明确迁移通道归一，运行时不建立无期限兼容层

### 提示词注入契约

提示词配置通过六个 DSH 官方插入点生效，各插入点保持独立：

- **R-PROMPT-01**：支持 `pre-step`、`system-section`、`runtime-context`、`agent-request`、`llm-stream` 和 `tool-pipeline`
- **R-PROMPT-02**：每个插入点只接受其能力矩阵允许的字段；不支持的字段在保存或挂载前失败
- **R-PROMPT-03**：`order` 只在同一插入点内比较；UI 与写盘顺序不定义运行时全序
- **R-PROMPT-04**：`position` 只定义配置在所属插入点内的锚点相对位置
- **R-PROMPT-05**：支持 `static`、`first-turn-anchor`、`guide-auto`、`custom-fallback`、`instruction-hint`、`placeholder` 和 `world-book` 内容策略
- **R-PROMPT-06**：消息受众独立区分主会话、子代理和两者公用；模型范围另行判定
- **R-PROMPT-07**：`separate` 保持独立消息，`merged` 在同一位置按层内顺序合并文本
- **R-PROMPT-08**：单一来源内的重复配置 ID 直接失败；跨来源同名 ID 按预定优先级覆盖
- **R-PROMPT-09**：配置文件使用四位数字前缀，从而在超过十条时仍保持稳定字典序
- **R-STRATEGY-01**：`first-turn-anchor` 根据首条真实用户消息分类任务，并在该 epoch 只注入一次锚句
- **R-STRATEGY-02**：`guide-auto` 在晋升后按任务复杂度每轮选择引导文本，且不与首轮锚定合并
- **R-STRATEGY-03**：`custom-fallback` 在锚定确认后注入一次预设内容；两轮未确认时执行兜底注入
- **R-STRATEGY-04**：锚定确认词缺省从锚句派生，显式确认词覆盖派生结果
- **R-STRATEGY-05**：`instruction-hint`、placeholder fill 和 context gate 共用同一文件探测与转换语义

### 参数、变量与模型路由

预设参数与内容变量使用两条互不混合的存储和校验通道：

- **R-PARAM-01**：普通引擎行为值属于预设参数；主会话和子代理模型路由使用各自的顶层段
- **R-PARAM-02**：新预设参数同时获得类型、键登记、保存校验、运行消费、客户端转换和契约测试
- **R-PARAM-03**：字符串 `''` 和空列表 `[]` 删除已存预设参数键；`0` 和 `false` 原样保存
- **R-PARAM-04**：`undefined` 和 `null` 表示本次不修改；它们不表示清空
- **R-PARAM-05**：模板变量允许空字符串占位值；预设参数键不得物化为模板变量
- **R-PARAM-06**：停用模板变量时不生成变量文件，并移除预设变量引用；宿主内置变量仍保留
- **R-PARAM-07**：客户端只发送已存键或用户已改动的键；显示用默认值不固化进预设
- **R-PARAM-08**：模型 `provider` 自动预选只用于显示；用户显式选择模型后才保存路由
- **R-PARAM-09**：未知键、类型错误、非有限数值、越界数值和非法阶段结构在落盘前返回稳定错误
- **R-PARAM-10**：旧版扁平模型键可读，但下一次保存将其迁移到对应模型段并清理旧键
- **R-PARAM-11**：正常保存触发一次重建；`rebuild: false` 只落盘，后续预设切换只对目标预设重建一次

### Bridge 与持久化

Bridge 在共享契约、本地信任边界和原子写入内运行：

- **R-BRIDGE-01**：`host` 和 `client` 共用同一份端点、请求与响应契约
- **R-BRIDGE-02**：成功响应统一为 `{ ok: true, value }`，失败响应统一为 `{ ok: false, code?, message? }`
- **R-BRIDGE-03**：`bridge` 只接受 loopback socket 上的 `POST`；Host 与可选 Origin 必须是同端口 loopback 来源
- **R-BRIDGE-04**：所有 JSON 端点限制为 32 MiB，角色卡原始流端点单独限制为 64 MiB；超限返回 `413` 和稳定错误码
- **R-BRIDGE-05**：畸形 JSON 和错误的请求结构返回 `400`，且不得退化为读取或空操作
- **R-BRIDGE-06**：首屏载荷只返回工作台需要的设置、元数据、参数、模板变量、提示词配置和模块事实
- **R-BRIDGE-07**：完整工具 Schema、执行实现、未知行级配置、大文本、路径和秘密不进入客户端载荷
- **R-DISK-01**：增量更新 YAML Ain’t Markup Language（YAML）时保留注释和未知字段；整体替换字段仍先完成类型校验
- **R-DISK-02**：文件先写入同目录临时文件，再原子 `rename`；失败后保留旧文件
- **R-DISK-03**：预设物化先在临时目录完整生成和校验，再替换目标并保留可恢复备份
- **R-DISK-04**：所有 ID 和导入路径在创建目标前通过包含性和宿主命名校验
- **R-DISK-05**：对 system 预设的所有写入端点返回只读错误；编辑必须先复制为用户预设

### 工作台与交互

工作台使用宿主官方界面与生命周期，不建立平行应用壳：

- **R-UI-01**：宿主设置页只承载部署设置和默认预设；完整编辑位于工作台
- **R-UI-02**：工作台使用已声明的三个官方 `slot`，不查询宿主 Document Object Model（DOM）结构或创建独立 React root
- **R-UI-03**：页面 ID 与顺序固定为 `features`、`subagent`、`skills`、`presets`、`characters`，默认显示主会话
- **R-UI-04**：每次打开工作台只聚合读取一次 `bootstrap`；搜索、筛选和排序在客户端完成
- **R-UI-05**：模型目录在工作台挂载后独立加载，不阻塞 `bootstrap`；预设工具面只在显式进入能力视图时加载
- **R-UI-06**：参数与提示词保存严格串行；失败任务不阻塞后续任务
- **R-UI-07**：保存成功只确认请求快照；请求期间的新草稿保持 `dirty`
- **R-UI-08**：较旧读取和静默刷新不得覆盖较新草稿或不完整阶段编辑
- **R-UI-09**：破坏性操作使用局部确认；错误靠近对应字段，公共通知使用 `role=status`
- **R-UI-10**：顶层导航和筛选 `tabs` 支持 roving tabindex、自动激活和稳定的 `tab`/`tabpanel` 关联
- **R-UI-11**：对话框支持 Escape、Tab 焦点循环和关闭后的焦点恢复；抽屉支持打开聚焦、Escape 和关闭后的焦点恢复
- **R-UI-12**：样式使用 Cascading Style Sheets（CSS）Modules 和 DSH 语义 token，并覆盖明暗主题、窄屏和 reduced-motion
- **R-UI-13**：能力卡只显示当前预设显式装配的能力；删除声明时保留 dormant 参数
- **R-UI-14**：当前会话模型使用宿主 sessions projection 读取，并通过官方会话选择通道更新
- **R-UI-15**：侧栏折叠、展开、拖拽和窗口断点变化时，悬浮入口持续贴合官方侧栏轨道
- **R-UI-16**：悬浮触发器和抽屉通过 `body` portal 挂载；打开工作台时通知其他插件面板保持互斥
- **R-UI-17**：首次无数据时显示骨架，刷新时保留已有数据，保存时只禁用冲突操作
- **R-UI-18**：超长路径、模型名和预设名使用单行省略，并通过可读描述保留完整值
- **R-UI-19**：模块参数的可见名称使用简洁简体中文，不直接暴露内部字段名、英文枚举或实现说明；底层键和值保持不变，未知枚举仍可回显原值
- **R-UI-20**：字段说明统一通过 `HintTooltip`；只复用宿主 Tooltip 的视觉 token 与尺寸，定位由本插件的 `body` portal 完成。鼠标悬停 500ms 后在指针附近显示并随指针移动，键盘聚焦时紧邻控件显示；错误、警告和状态信息仍就地显示
- **R-UI-21**：开关名称位于开关上方并与输入框、选择框使用同一字段节奏；人设关闭后出现的段名与人设、独占、动态抑制在宽卡片保持同一行

### 工具、技能目录与预设操作

工具和技能复用 DSH 官方注册与生命周期，工作台只编辑 Prompt Tool 拥有的声明：

- **R-TOOL-01**：自定义工具使用声明式参数和 `shell`、`http`、`delegate`、`fs` 或 `ask-user` 执行器
- **R-TOOL-02**：工具参数先转换为官方 Schema；非法参数返回标准工具错误且不执行
- **R-TOOL-03**：`requireApproval` 在执行前触发宿主审批；`delegate` 通过官方工具运行时完成嵌套调度
- **R-TOOL-04**：自定义工具的未支持 `scope` 在保存期间明确拒绝，不得静默忽略
- **R-TOOL-05**：工具面只返回名称和描述；当前会话与显式选定预设的视角均保持只读
- **R-SKILL-01**：引用技能目录只保存绝对路径，导入文件夹则复制内容到生效技能目录
- **R-SKILL-02**：移除目录引用不删除原目录；同名技能全部展示，模型注册只采用首个有效目录
- **R-SKILL-03**：技能页支持搜索、状态筛选、单项或批量启停、键盘排序、重扫、修复与打开目录
- **R-PRESET-UI-01**：当前预设不得删除；不可渲染预设不得切换
- **R-PRESET-UI-02**：新建、导入、复制、删除和切换完成后重新同步预设清单与当前状态

### Epoch、PTC 呈现与子代理

运行时状态从持久会话事件恢复，而不是依赖进程内偶然顺序：

- **R-RUNTIME-01**：晋升信号来自持久 `tool/call`、`assistant/message` 事件之一或两者
- **R-RUNTIME-02**：成功 `compaction/end` 开始新晋升 epoch，失败压缩保持原相位；`context-gate.instructionHint` 以模型可见 surface 去重，仍可见时跳过、被遮蔽后重新武装
- **R-RUNTIME-03**：子代理缺省视为已晋升；只有显式 `includeSubagents` 才跟随主会话阶段
- **R-RUNTIME-04**：严格门控模式同时检查首段 reasoning、工具调用、步数上限和可选首次回复兜底
- **R-RUNTIME-05**：渐进披露阶段由持久工具调用事件推导；恢复和重载重建同一阶段
- **R-RUNTIME-06**：调用高阶段工具可直达该阶段；压缩不重置渐进披露阶段
- **R-RUNTIME-07**：PTC 呈现与工具目录窄化是可独立组合的 opt-in 能力
- **R-RUNTIME-08**：所有监听器、工具、`watcher` 和动态服务随 `scope` 释放，重挂前先调用 `disposer`
- **R-SUBAGENT-01**：子代理工具策略保持 opt-in，并包含授权上限、默认工具档、工具档、角色绑定、有序任务规则和受控模型扩权
- **R-SUBAGENT-02**：`deny` 始终优先；所有工具档和扩权结果都不得超过授权上限
- **R-SUBAGENT-03**：有序任务规则按层内顺序取首个匹配；无匹配时使用默认工具档
- **R-SUBAGENT-04**：预览与运行时使用同一解析规则；预览不创建子代理
- **R-SUBAGENT-05**：子代理创建时冻结工具过滤；已运行实例不接受热扩权
- **R-SUBAGENT-06**：需要审批但宿主没有审批通道时拒绝扩权；`provider` 缺少必需能力时在启动前失败

### SillyTavern 预设与角色资产

转换仅映射外部资产明确声明的内容，不添加 Prompt Tool 默认提示词：

- **R-ST-01**：只含单个 SillyTavern JSON 且不含预设定义的导入包自动转换为普通预设
- **R-ST-02**：空 `content` 条目跳过；Universally Unique Identifier（UUID）形态 identifier 转为稳定序号 ID
- **R-ST-03**：system prompt 映射为可按层内顺序合并的 `system-section`；其他角色映射为对应的 `pre-step`
- **R-ST-04**：启停状态、角色、位置和声明顺序保留；采样参数和第三方扩展脚本剔除
- **R-ST-05**：启用 web search 时显式装配工具能力；停用时显式拒绝 web 工具
- **R-ST-06**：`setvar` 和 `getvar` 转为模板变量；未定义自定义宏登记为空占位值
- **R-ST-07**：插值优先级为 resolved 运行值、会话变量、配置变量、预设变量、运行时宏、内置环境值、字面保留
- **R-ST-08**：PNG 角色卡优先读取 `ccv3`，再回落 `chara`；支持明文和 zlib 压缩负载
- **R-ST-09**：角色卡导入角色卡库后不直接改变任何预设
- **R-ST-10**：应用角色卡时用稳定前缀合并人设、开场白、世界书和角色记忆；重复应用保持幂等
- **R-ST-11**：从预设移除角色卡只删除该前缀的合并内容；删除角色卡库资产不回滚已合并内容
- **R-ST-12**：世界书支持常驻、主关键词、副关键词、正则、大小写、全词和选择逻辑
- **R-ST-13**：无关键词且非常驻的世界书条目按全局条目每轮注入
- **R-ST-14**：角色记忆归属角色卡并跨会话保留；无角色归属的 note 回落到预设记忆

## 测试决策

测试验证最高层可观察行为。实现优先复用现有 `host`、Engine、`client` 和 shared contract 验收面，不为本规格新增测试框架。

### 按公开输入划分验收面

每个验收面从一个公开输入验证到一个用户可观察结果：

| 验收面 | 输入 | 可观察结果 | 现有测试先例 |
|---|---|---|---|
| 预设物化 | 合法或非法预设定义 | 完整可解析产物，或无部分写入的失败 | `host` 预设、组合和 `writer` 契约测试 |
| 提示词注入 | 提示词配置与会话事件 | 六个插入点的正确内容或控制行为 | Engine 策略、插值和提示词执行测试 |
| 参数保存 | 客户端快照与 `bridge` 请求 | 正确的落盘值、`dirty` 状态与重建次数 | 参数契约、`dirty` 状态和保存队列测试 |
| Bridge 安全 | 方法、Host、Origin、JSON 和载荷大小 | 稳定响应封装、错误码与零落盘 | shared contract 与 `host bridge` 测试 |
| 工作台 | `slot` 注册、用户交互与异步响应 | 稳定导航、焦点、草稿和请求数 | `client` 结构、可访问性和状态测试 |
| Epoch 生命周期 | 持久会话事件序列 | 恢复、晋升、压缩后重置和 `disposer` | Engine 晋升、门控和阶段测试 |
| 子代理策略 | 授权上限、选择器与创建请求 | 预览与运行一致的冻结工具集 | 纯解析器与运行时策略测试 |
| SillyTavern 转换 | 预设卡片、角色卡与世界书 | 符合预设契约的可编辑结果 | `host` 转换、角色卡库和世界书测试 |

## 非目标

本规格固定当前框架边界，不扩大 DSH 或 Prompt Tool 的产品范围：

- 修改 DSH 源码、官方 bundle 顺序或 profile 装配
- 为六个官方插入点建立插件级全局调度器
- 将 PTC、首轮锚定、router-guide、Flash 路由或其他增强改为默认能力
- 在 `settings descriptor` 中保存预设行为、大文本、角色卡原文件或秘密
- 建立独立 React root、查询宿主 DOM、复制宿主导航或引入第二套主题系统
- 将预设工具面变为编辑入口，或让子代理策略预览创建真实代理
- 执行 TavernHelper、regex scripts 或其他 SillyTavern 第三方扩展代码
- 从 SillyTavern 资产覆盖 DSH 模型采样设置
- 手工编辑或提交生成目录
- 为尚未观测到的规模问题引入虚拟列表、第二套状态库或新测试框架
- 在本次交付中重启当前 DSH 服务或生成实现任务文件
