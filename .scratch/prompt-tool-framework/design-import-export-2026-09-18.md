# 导入导出重构建议与 UI 交互设计

- 日期：2026-09-18；源码核对基线：`627ba2d`，分支 `dev`。
- 输入：[导入导出审查报告](reviews/2026-09-18-import-export-review.md)。报告基线到本轮基线仅增加报告及其修订，业务代码未变。
- **已确认范围**：本轮交付设计方案与交互线框，供评审；不实施业务重构、不制作可运行原型。
- **已确认载体**：完整预设使用 ZIP，另保留“仅导出定义”。JSON/PNG/YAML 的单文件导入仍须支持。
- **既有决策**：YAML 同时支持 ST 角色数据和本项目原生 `converted.yml` 角色片段；PNG 的识别、解析、原图保留与导入能力必须保留。
- 状态：下文除上述已确认项外，均为推荐设计，不能作为已经实现或全部获批的行为承诺。实施获授权后再原文归档旧 `PLAN.md` 并创建新执行计划。

## 1. 推荐结论

将变化收敛到四个有真实消费者的职责：**输入识别与预览、预设安装、角色库更新、预设资源收集与导出**。延续现有 ST 转换、角色应用、writer、预览版本和 UI 状态机；让 bridge 只做请求适配。

UI 改为两页共用的“选择来源 → 检查内容 → 确认结果”导入面板，导出提供清楚的范围选择。模块化的验收是同一规则能被 Web、模型工具或 CLI 复用，且能独立做行为测试；不是增加目录层级或通用框架。

| 候选 | 收益 | 代价 | 建议 |
|---|---|---|---|
| 只调整页面、增加扩展名 | 工作量小 | F01–F14 的根因仍在，共享路径继续损坏资产 | 不采用 |
| 深化现有 host 职责、共用预览与资源规则 | 多入口得到一致行为，可分阶段验证 | 需要整理 writer 副作用与桥接契约 | 推荐 |
| 通用资产平台、动态格式 registry、任务中心 | 支持未知外部扩展 | 当前没有相应消费者，增加维护面 | 出现真实扩展需求后再评估 |

## 2. 从报告到模块边界

### 2.1 现状与目标

现状：页面按扩展名和大小分流 → bridge 内识别、转换和写盘 → writer 再修改目录；Web 导出、CLI 导出与复制各自解释资源和身份。

目标：各入口收集来源 → host 识别并生成预览 → 用户确认目标及覆盖行为 → 目标 owner 校验并提交。导出与复制共用 host 的身份定位和资源清单。

| Owner／建议文件 | 输入 → 输出／应拥有的规则 | 真实复用点 | 对应问题 |
|---|---|---|---|
| `shared/bridge-contract.ts`，必要时抽纯类型到 `shared/asset-transfer.ts` | 显式编码、来源定位、预览状态、版本、统一错误封装；不做文件 IO | client、runtime；继续由 bridge-contract 导出公开契约 | F04、F12 |
| 新增 `host/import-source.ts` | 文件字节＋来源描述＋目的 → 识别结果、候选选择、规范化定义和报告；不写目标 | 预设导入、角色导入、PNG 流、模型导入工具 | F03、F11、F12、F16 |
| 新增 `host/preset-package.ts` | 资源清单、完整候选验证、安装提交、ZIP 编解包；内部直接函数，不建 service/repository 层 | Web 包导入导出、CLI 导出、复制 | F01、F04–F09 |
| 既有 `host/manifest.ts` | 合法 ID、当前官方根、目录身份与归属定位；共享复制身份更新 | writer、包模块、复制、导出 | F05、F06、F09 |
| 既有 `host/write-preset.ts` | 在指定暂存目录物化单个预设；保留源正文和自有模块；共享引擎同步与单预设渲染分离 | 导入、保存、重建 | F01、F07 |
| 既有 `host/characters.ts` | 来源资产替换、记忆保留、真实应用计数、应用／移除；不承担通用预设 ZIP | JSON/PNG/YAML、流式入口、模型工具 | F02、F10、F13 |
| 既有 `host/preview-revision.ts` | 服务端绑定来源、语义选择、目标身份与版本；读取失败和目标不存在可区分 | 所有预览／提交 | F07、F12 |
| `runtime/settings-bridge.ts`、`runtime/character-tools.ts`、CLI | 检查传输边界、调用上述函数、统一返回；不复制转换、路径或事务规则 | 所有入口 | 全链路 |

先新增这两个有明确消费者的 host 模块，不以文件数作为硬指标。PNG 解码复用 `characters.ts` 的实际实现；import-source 和 characters 需要互相调用时，将解码器原样提取为一个共享小文件，避免循环依赖，并让提取脚本复用。**不以“客户端函数当前未接线”为由删除 PNG 能力。**

可复用 API 的概念轮廓为 `prepareImport(source, choices)`、`installPreset(prepared, expectedRevision)`、`collectPresetFiles(id, mode)`；角色持久化继续归 characters。名称在实施时对齐现有代码；本设计不预先制造第二套数据模型和接口包装。

## 3. 输入、预览与安装契约

### 3.1 载体与内容分开识别

先把文件夹、ZIP、单文件规整为有界字节集合，再识别内容语义。不能以 `.json` 代表 ST、以 `.yml` 代表原生预设、以 PNG 扩展名代替魔数。

| 输入 | 识别与预览 | 确认后落点 |
|---|---|---|
| 文件夹／完整 ZIP | 唯一顶层定义＋资源；允许一个统一外层目录，剥离一次 | 一个预设 |
| 原生预设 JSON／YAML | 同一原生 schema，保留参数、模块、promptConfigs 和未知字段；YAML 保留注释 | 一个预设 |
| ST 预设 JSON／YAML | 既有转换器、顺序组与有损报告 | 一个预设 |
| ST 角色 JSON／YAML／PNG | 同一角色语义；PNG 受限解码并保存原图 | 由进入页面决定“角色库”或“新预设” |
| 原生 `converted.yml` 角色片段 | 独立校验角色片段允许的配置；不按文件名直接判合法 | 角色库；或按显式目的生成新预设 |
| 世界书 JSON | 复用已有世界书转换 | 预设入口；角色库不接收独立世界书 |
| 不认识、结构矛盾、多个定义候选 | 返回定位错误或要求选择；绝不生成成功的空预设 | 零目标写入 |

JSON/YAML 原生预设与角色片段可能形状重叠：先用入口目的约束，再校验结构；仍歧义时展示“预设定义／角色片段”选择。选项来自服务端实际通过校验的候选，不允许强制忽略错误。

已有 `preset.yml` 时，其余 JSON/YAML 为附件，不能因为含 `prompt_order` 就参与转换。没有定义但存在多个可转换 ST 来源时，预设入口显式提供“合并为一个预设”，沿用现有合并与 ID 映射；角色库按文件逐张入库，不合成一张卡，避免 F10 的来源不完整。

默认定义选择不依赖浏览器文件枚举顺序。显式多来源合并的顺序则属于用户选择，必须展示并纳入版本；不能为了排序稳定而改变合并语义。

### 3.2 字节和路径

小包的传输项建议为 `{ path, encoding: 'base64', content }`，host 解码后再按内容读取文本；不混用“有时正文、有时 base64”的无标记字符串。复用现有 `readImportFiles` 的字节读取能力并修订共享契约。大文件保留原始流，按同一 source 语义进入预览。

流式上传只写插件拥有的暂存区，返回不透明来源句柄；不直接更新预设或角色库。句柄与受校验的请求上下文绑定、具备有效期，不能充当目标授权或接受任意服务器路径。取消、过期、卸载和启动恢复时清理本插件暂存数据；不扫描清理用户目录。

文件夹、ZIP 和流式路径共用拒绝规则：绝对路径、上跳、盘符／UNC、Windows ADS、链接／junction 越界、重复规范化路径与大小写碰撞。限制文件数量、单文件及总解码／解压大小；实际读取过程中继续计数，不能只相信 ZIP 元数据或 Content-Length。PNG 继续保留 chunk 边界和解压上限。

ZIP 库在实施时选型：当前未声明直接 ZIP 依赖，应优先选择一个成熟、支持有界读取的库，核对许可证和维护状态；不要自己写 ZIP，也不调用依赖用户机器环境的压缩命令。不在本设计轮安装依赖。

### 3.3 预览版本与提交

预览应返回：来源名称和识别类型、目标 ID／名称、文件与字节汇总、将新增／替换／保留项、缺失依赖、转换报告、顺序组或类型候选、服务端版本。候选状态没有提交凭据。

版本绑定规范化来源的字节摘要、显式合并顺序、转换器版本、目标类别／ID／当前版本、选组及覆盖模式。提交重算且必验；版本摘要不是授权。目标不存在与目标无法读取必须分开，读取失败不能当作新建。

同名冲突默认建议“另存为新 ID”，允许用户明确选择覆盖；系统／只读目标只允许另存。服务端返回可用 ID，用户可编辑，预览前后都按 writer 的合法语法和根归属规则验证。改目标、模式、选组或文件后，旧确认资格立即失效。

Web 每次确认都引用当前预览；模型工具可以共用同一识别与持久化函数，但继续遵守自身工具授权，不把“要求点击网页按钮”作为 host 的通用授权规则。

### 3.4 安装成功的定义

1. 目标定位通过白名单与身份校验；等待同目标操作串行执行。Web 对当前预设的未保存草稿沿用现有保存队列，保存失败阻止覆盖。
2. 在同一文件系统的插件暂存目录构造完整候选，用 YAML Document API 修改 ID 等必要字段。
3. 先复用 `validateCustomTools()`、提示词引擎权威校验和现有保存校验，拒绝无效工具、配置、模块与子代理策略；再用真实 writer 在暂存目录物化。现有 writer 对坏工具告警跳过，不能把“不抛异常”当作完整验证。文件引用校验必须显式针对候选目录，避免引擎按自身 import.meta.url 读到旧目标。物化传入最终目标身份，避免把暂存目录名写入相对引用。
4. **单预设候选物化不修改共享 `.engine` 或兄弟预设。** 共享引擎由插件现有生命周期独立同步；候选只验证其可用性。writer 的现有共享副作用须先拆出，不能只在 bridge 外面包 try/catch。
5. 在交换前再次检查目标版本；旧目标改名为备份，再将完整候选 rename 到目标。任一步失败恢复旧目标；恢复失败保留备份和可诊断位置，不继续删数据。
6. 文件安装完成后才返回安装成功。安装后的清单刷新失败标注“已导入，列表刷新失败”，不能伪装成未写入并自动重试覆盖；导入不自动切换活动预设。

现有 writer 遇到 Windows 目录占用时会退到 `syncDirInPlace()`，逐项覆盖并删除多余文件。该回退不能作为新安装事务的原子保证：导入提交遇到占用应保留旧目标、返回可重试错误，不退化为无完整恢复保障的原地覆盖。可复用的是候选生成能力，不是原样嵌套现有提交流程。

rename 交换提供受控错误恢复，但多目录更新不是单次原子事务；不宣称能消除所有进程崩溃窗口。中断时保留有限的恢复记录和备份，启动时只诊断／恢复本插件未完成操作，不靠清空残留目录处理。

角色库沿用自身事务：更新来源文件与转换定义时保留独立 `memory.md` 和非本轮拥有的用户文件；新 PNG 替换头像，未提供头像的 JSON/YAML 更新建议保留旧头像。交换前复检目标版本，并与记忆追加在同一角色粒度串行，避免复制旧记忆覆盖并发新增。原生片段的内嵌 `text/texts`、控制配置按实际引擎契约保留，应用计数以实际新增配置为准。

原生角色片段首版建议只接纳自包含内容；角色库入口遇到 `templateFile` 等文件引用明确拒绝并指出配置，不能静默跳过。带附件内容可走完整预设文件夹／ZIP 入口，由预设拥有附件、按最终引擎位置生成引用。角色库附件支持若后续纳入范围，须另外定义“来源附件留库、应用副本归预设、显式所有权记录、移除只清理无消费者副本”的契约，并验证跨 DSH_HOME 实际读取；本轮不把它当作已解决能力。

## 4. ZIP、定义导出与复制

### 4.1 导出内容

| 内容 | 完整 ZIP | 仅定义 |
|---|---|---|
| `preset.yml` 权威定义 | 包含 | 包含，下载 `.preset.yml` |
| `preset.md`、预设自有正文／图片／附件 | 包含，逐字节保留 | 不包含，显示缺失资源数量 |
| 用户维护的组合、本地 `engine/*.mjs` 及其同根依赖 | 包含；仅改有明确所有权的生成引用 | 不包含 |
| 可再生配置目录、缓存、暂存、备份 | 不包含，由目标重建 | 不包含 |
| 插件共享 `.engine` | 不复制安装副本；记录插件版本要求，目标从已安装插件生成 | 仅声明依赖 |
| 角色库来源文件、`memory.md`、技能库 | 不随预设打包；有关联时列为外部依赖 | 不包含 |
| 工作区 `AGENTS.md`／`CLAUDE.md` 及 local 变体、独立指令策略 | 不读取、不打包 | 不包含 |

预设自身的 `agents.md` 内容资产与用户工作区的 `AGENTS.md` 指令文件须按所有权区分，不能只靠大小写或文件名做筛选。

建议 ZIP 布局为单一 `<id>/` 根，内含权威定义、自有文件，以及小型清单 `prompt-tool-package.json`。清单只记录交换格式版本、根／定义路径、插件兼容要求和文件摘要，不复制预设行为。没有清单的普通文件夹仍可按唯一候选规则导入；不强制老目录迁移。

定义仍是行为的唯一来源。ZIP 清单与原生 YAML 不一致时拒绝，不能选择“看起来更完整”的一份静默修正。导出前后复检来源版本，禁止边保存边收集形成混合快照。

**依赖处理**：根内相对文件全部保留；缺文件、向根外读取或未随包提供的角色库依赖，在导出预览中列明并阻止宣称“完整可移植”。用户仍可选择仅导出定义并看到限制。npm／宿主／插件依赖是运行前提，列出版本要求，不扫描本机复制依赖目录。JS 动态构造路径无法靠静态分析证明完整性，归为待检查外部依赖；不引入通用 JS 依赖解析器。

已展开到预设里的自包含角色配置可导出；只有仍需读角色库文件的能力才计作缺失依赖，不能仅因 `meta.importedCharacters` 非空就阻止所有角色预设导出。角色库的后续更新／移除能力与预设运行恢复也应在预览中分别说明。

### 4.2 角色记忆的隐藏副本

当前 [applyCharacterToPreset](../../src/host/characters.ts) 会把角色记忆注入 `promptConfigs` 的 `chara-<id>-memory` 项。因此只排除 `memory.md` 文件，仍可能把记忆正文带入 ZIP 或单定义导出。

推荐两种导出共用“可分享定义”投影，在副本中排除有来源证明的自动记忆，不改磁盘原定义。当前 `meta.importedCharacters` 加 ID 不足以证明来源：原生卡自己的 `id: memory` 也可能得到相同前缀 ID。

建议角色应用／记忆同步由宿主维护独立的生成项来源记录（角色 ID、实际配置 ID、生成内容摘要），导入文件携带的记录不能直接成为可信证明。分配记忆配置 ID 时检测与用户条目冲突，使用未占用 ID 并记录，后续同步按记录定位；不覆盖同名普通配置。导出验证来源记录和当前内容相符再排除，不以任意 `*-memory` 名称猜测。

旧数据或用户改过生成项时，先用角色库与原生片段核对；仍不能唯一判断的，建议阻止两种出口的默认下载，并列出具体条目让用户明确“排除”或“作为普通内容保留”。选择、来源与目标版本一起重新校验；选择保留后界面明确提示包含相应内容，不再展示“不含角色记忆”。用户手工粘贴到普通提示词里的文本不靠语义猜测删除。

自动记忆投影排除是本方案新增的待评审建议，不是报告已经验证的修复。应新增行为断言：合成记忆标记不出现在 ZIP 内任何文件或定义导出中；原预设和角色记忆字节不变。

### 4.3 复制与兼容

复制复用资源收集规则和候选验证，但不必先压 ZIP 再解 ZIP，也不套用分享出口的记忆过滤：同一安装内复制保留原有行为与角色关联。新目录 ID、定义 ID 以及引用身份一起更新，来源不变；YAML 注释和未知字段保留。

CLI 与 Web 共用当前 `.agent-presets` 定位规则，包内模板仅按既有允许条件回退。旧根不再抢先匹配；若未来保留兼容入口，应显式指定，不能静默优先。

bridge 先改共享契约，再接 host 和 client。建议保留现有端点作为薄适配，显式区分新字节载荷与已知旧文本载荷；没有编码标记的旧二进制输入拒绝并提示刷新页面，不靠扩展名猜测。PNG 流式直接提交行为退役为“上传暂存 → 预览 → 确认”，旧客户端收到明确升级提示。

## 6. 交互线框

以下均为示例数据，表示设计目标，**不是运行截图**。

### 6.1 入口：保持页面语境

```text
预设                                            [新建] [导入…]
管理预设及其自有资源

● 日常助手                 当前预设            [更多 ▾]
  描述与可用状态
○ 故事写作                                     [更多 ▾]

更多：复制 / 导出… / 打开位置 / 删除
```

“导入…”统一容纳文件和文件夹，避免工具栏铺开多种格式按钮。“导出…”必须明确显示操作对象，不能把选中预设与当前活动预设混为一谈。

角色页仍是角色库；入口名为“导入角色卡…”。入库完成后才提供“应用到当前预设”，不隐式修改当前预设。预设页导入角色内容的动作名为“从角色卡创建预设”，不偷偷同时写角色库。

### 6.2 选择来源

```text
导入预设                                                [关闭]
1 选择来源     2 检查内容     3 完成

选择预设包、预设文件或角色卡
支持 ZIP、JSON、PNG、YML、YAML，也可选择预设文件夹

                [选择文件]  [选择文件夹]

文件选择完成后自动识别；此时不会更新预设。
                                                        [取消]
```

不新增必须拖放的交互；使用 `ImportFileButton` 和原生文件输入。角色页支持多文件，按原选择顺序逐张预览；文件夹和 ZIP 是一个导入单元。初版不新增无限队列、拖拽排序和全局任务中心。

### 6.3 检查内容：无冲突

```text
检查导入内容                                            [关闭]
1 选择来源     2 检查内容     3 完成

来源  星港助手.zip              已识别：原生预设
内容  8 个文件 · 428 KB         12 条提示词配置

名称  [星港助手                         ]
标识  [starport                         ]

将新增一个预设
▾ 文件与资源（8）
  preset.yml         预设定义               新增
  preset.md          正文                   新增
  assets/avatar.png  图片                   新增
  engine/check.mjs   本地模块               新增

▾ 需要检查（2）
  2 条提示使用兼容转换                     [查看具体条目]
  不支持的扩展脚本不会执行                 来源：extensions…

导入后可在预设列表中使用。
                         [重新选择] [取消] [创建预设]
```

摘要和目标先于诊断长列表；警告／阻塞默认展开，无问题的附加详情可折叠。文件清单展示“新增／替换／保留”的文字状态，长路径可换行，不能只有颜色或截断后的名字。

原生输入也有资源与目标预览，不能因为没有 ST report 就显示“无报告”后让用户盲目确认。ST 多组时在诊断上方显示“提示顺序组”单选；未选组只显示候选，不显示已经转换成功的数量。

### 6.4 同名角色更新与覆盖

```text
检查角色卡                                              [关闭]

[头像]  星港导航员              已识别：PNG 角色卡
        原图已读取 · 人设 / 开场白 / 世界书

角色库中已存在相同标识：starport-guide
● 另存为新角色   标识 [starport-guide-copy ]

  替换：角色来源、转换配置、此次提供的头像
  保留：角色记忆、其他不归本次导入所有的文件

  展示具体来源 → 目标及兼容变化

```

覆盖需使用现有 `ConfirmDialog` 的 alertdialog、取消首聚焦及危险按钮样式；一次确认只针对一个明确目标。关闭预览后进入确认，再取消覆盖则回到同一预览，避免叠两个焦点陷阱。候选变化或版本过期后，覆盖授权与旧预览一起失效。

角色批次页头显示“第 2 / 3 张”，提供“跳过这张”和“结束本次导入”，语义分开。不能把“取消”含糊地解释为仍继续提交后续项目。成功结果显示已导入／跳过／失败数，各项失败可定位；逐卡提交不宣称整个批次原子成功。

```text
  运行前提：Prompt Tool 与宿主兼容版本

○ 仅预设定义 YAML
  适合查看或分享配置，不包含引用的附件。

  预设定义 / 正文 / 图片 / 自有模块

不包含：角色记忆文件、工作区指令、技能库和机器配置。

发现缺失资源时：
  无法生成完整包：rules/extra.md 不存在
  [返回修复] 或选择“仅预设定义”查看限制

                              [取消] [导出 ZIP／导出 YAML]
```

导出由单选框表示互斥范围，不用两个外观同权重且含义模糊的下载图标。资源缺失只阻塞完整模式；仅定义仍明确显示依赖缺失。记忆来源不明则按 §4.2 先处理条目，两种下载均不能绕过；“已排除”数量来自本次真实投影，不使用固定承诺。浏览器下载启动后文案为“已生成，浏览器已开始下载”，不声称文件已保存到磁盘。

```text

                                         [完成] [切换到该预设]
```

## 7. 视觉、响应式和状态规格

### 7.1 视觉规格

| 项目 | 设计值／约束 |
|---|---|
| 风格 | 沿用 DSH 紧凑工作台；平面分区、少量边框，一个主要动作，无渐变、光晕或新增装饰动画 |
| 容器 | 预览面板建议最大 760px，导出／确认保持现有紧凑规格；最大高度 `100dvh` 减安全区与 24px 外边距 |
| 实现边界 | 现有 DialogSurface 固定 440px；可增加有真实用途的 `size` 选项及 CSS modifier，默认不变，不重写焦点逻辑 |
| 布局 | 标题与操作栏固定在面板内，中间正文为唯一主要滚动区；用 flex 分区，避免浮动底栏遮挡错误 |
| 字体 | 沿用宿主字体；标题使用宿主 strong token，正文目标 13–14px，次要信息 12px；数量使用 tabular-nums |
| 间距 | 小项 8px，分区 16px，内容边距桌面 20–24px、窄屏 16px；细节按宿主已有节奏对齐 |
| 表面／文字 | `--dsw-alias-bg-layer-2`、`--dsw-alias-label-primary`、`--dsw-alias-label-secondary` |
| 边框／焦点 | 0.5px `--dsw-alias-border-l1/l2`；focus-visible 使用 `--dsw-alias-state-business-primary` |
| 危险／浮层 | 复用 `ConfirmDialog` 的描边危险样式、`--dsw-elevation-prominent` 和既有 portal 层级 |
| 图片 | 头像固定尺寸与比例、object-fit；有名称或装饰性 alt，失败显示有意义的占位；不改变原始导入图片 |
| 文案 | “来源、识别结果、保存到、替换、保留、需要检查”；协议名、哈希和 JSON 载荷不作为主界面信息 |

### 7.2 响应式与无障碍

- 面板可用宽度 ≥640px：摘要可两列，文件清单用语义表格；不足 640px：单列，文件项改为标签和值，不产生横向溢出。
- 320px 起可操作；窄屏按钮换行或等宽排布，触控热区至少 44px；长文件名 `overflow-wrap:anywhere`，禁用不靠透明度单独表达。
- DialogSurface 复用 focus trap、Escape、关闭后焦点恢复；预览进入时聚焦标题，错误时聚焦错误摘要。危险确认聚焦取消。
- 目标名称、ID、单选范围和选组都有可访问名称；错误通过 aria-describedby 关联字段，非法项设置 aria-invalid。
- 状态使用 `role=status`／aria-live=polite，阻塞错误使用 alert；进度无实际总量时显示阶段文字，不伪造百分比。按钮禁用旁必须有原因。
- 步骤条为有序列表与 aria-current，不伪装可随意切换的 tabs。可折叠详情使用原生 details，或复用已有受控展开组件。
- 用户文件名、诊断和内容作为文本渲染，不使用危险 HTML。所有文案加入现有 zh/en 字典；明暗主题、200% 缩放、reduced-motion 均列入验收。

### 7.3 统一生命周期

| 状态 | 用户看到什么 | 可执行动作与约束 |
|---|---|---|
| 未选择 | 格式与目的说明 | 选择文件／文件夹、取消 |
| 读取／上传 | 来源名、已知字节进度或阶段文字 | 可结束读取；拒绝第二次并发选择并说明忙期 |
| 待选择类型／顺序组 | 实际候选与差异 | 选择后重新预览；不能提交 |
| 预览就绪 | 目标、替换／保留清单、报告 | 确认、改目标、重新选择、取消 |
| 重新预览 | 旧内容可见但标“正在更新” | 旧确认禁用，迟到响应不能恢复旧资格 |
| 提交中 | “正在安装，请稍候” | 禁重复提交；不能声称取消客户端请求已回滚服务器 |
| 过期 | 所选文件与选项保留，旧报告标失效 | 重新预览，不能直接重试旧提交 |
| 可恢复失败 | 就地原因及磁盘状态 | 重试前重新确认版本；保留来源，不自动重传覆盖 |
| 成功／刷新失败 | 明确区分安装结果与列表刷新 | 完成、显式切换；或仅重试刷新 |

此表是未来目标：当前状态机过期会关闭预览，流式路径直接提交。不能把设计当作现状改文档。无需增加后台任务系统；只有真实测量表明一次有界导入超出请求生命周期，才另提 Init/Step/Poll 需求。

### 8.1 最小回归矩阵

| 场景 | 必须断言 |
|---|---|
| 原生 JSON／YAML 等价 | 同一配置、参数和模块保留；未知／矛盾结构拒绝，YAML 注释和未知字段保留 |
| PNG 单文件／文件夹／ZIP | 角色数据一致，原图 SHA-256 相等；截断 chunk、解压越限拒绝；取消不入库 |
| 两类 YAML 角色 | ST 数据与原生片段分别识别；text/texts/控制配置真实应用数正确；角色库拒绝未支持的文件引用，完整预设包实际读取候选附件 |
| 目录枚举与合并 | 单定义与附件无关；调换枚举顺序结果稳定；显式合并顺序保持且改变版本 |
| 覆盖与并发 | 目标改变、两窗口确认、记忆并发追加、读失败均不能静默丢数据；记忆保持字节完整 |
| 安装故障 | 坏工具／配置不能靠 writer 跳过而成功；校验只读候选附件；写盘、物化、rename 与恢复失败分别注入；响应与磁盘事实一致，无兄弟目录变更 |
| ZIP 边界 | Zip Slip、绝对路径、链接、重复／大小写碰撞、超量与损坏包拒绝，零目标写入 |
| 导出与复制往返 | 新旧根共存选当前根；新 ID 一致；异地临时 DSH_HOME 真实物化后正文、图片、模块引用有效 |
| 独立所有权 | 指令正文／策略不读不写不导出；有证明的自动记忆在两种出口均排除；普通 id: memory 不被误删，旧条目需明确选择；复制保留关联，磁盘源保持原样 |
| UI 生命周期 | File 读取失败有反馈；双击互斥；选组迟到响应无效；过期需重预览；卸载不提交下一张；批次结果真实 |

延用 Node test runner 和现有 helper；高风险既有测试单独保留，不合并压缩。对应执行 shared bridge、host 包导入／角色／writer、client import-smoke 及受影响 engine/presets 契约；最终完整测试，不以静态字符串匹配替代文件行为。

所有测试和验证脚本从隔离 cwd 运行，文件系统用独立临时 DSH_HOME，浏览器用随机端口并自行清理：

```powershell
$Repo = 'D:\AI\GitHub\dsh-plugin-prompt-tool'
Set-Location 'D:\AI\workspase\_temp'
pnpm --dir $Repo typecheck
pnpm --dir $Repo lint
pnpm --dir $Repo test
pnpm --dir $Repo build
git -C $Repo diff --check
```

回滚按 Wave 保留独立提交和原格式入口适配；数据交换失败只恢复该目标备份。已经导入的用户数据不能靠 git revert 恢复，禁止借回滚清理角色记忆、其他预设或用户指令。源码实施后按实际构建／profile 变化提示用户重启 DSH，代理不操作运行中服务。
