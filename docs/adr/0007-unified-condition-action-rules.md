# 统一条件与动作，互斥由显式启用事务决定

状态：本决策的**架构方向继续有效**（所有行为统一为规则的条件树与动作数组、互斥由显式启用事务决定）；仅**字段名已更新**——条件树由 `when` 改为 `if`，动作数组由 `do` 改为 `then`，并新增动作级 `else` 承接另一分支。旧名在声明路径被显式拒绝（`engine/rule-spec.mjs` 报「`when` 已退役，改用 `if`」）。下文保留原决策记录中的旧名，不改写。

独立的提示词配置、模块触发器和旧快捷参数造成了多套行为来源，也让卡内设置不断嵌套。按用户明确选择，每条配置仍保留独立卡与身份，但所有行为统一为 `module.yml.rules` 的条件树 `when` 和动作数组 `do`，提示词注入属于动作；总入口编译并调度，判断与执行分别由引擎内的条件模块和动作模块拥有。

本决策延续 [ADR-0001](0001-preset-definition-is-authoritative.md) 的单一定义源和 [ADR-0006](0006-module-config-order.md) 的身份排序，替代旧 `promptConfigs` 与 `triggers` 并存的表示。旧格式只经显式离线预检、备份、转换和回滚处理，不保留运行时双读；业务正文、匹配词、阈值与模型偏好移入模板或规则，协议和资源保护继续由引擎保证。

互斥是同模块同组的保存约束：组内任一成员声明互斥时，显式启用目标卡会原子关闭其他成员的总开关。重排不改变启用状态；无显式选择的多启用冲突拒绝保存与挂载，不再按排序挑赢家。该选择让多卡关联、独立排序和多动作组合同时成立，代价是旧冲突必须在离线迁移前明确整理。
