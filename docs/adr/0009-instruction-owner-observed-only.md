# 指令负责人事实只报告观察到的官方装配

状态：已采纳，2026-10-10。

## 决策

`instructions.owner.officialInstructions` 三态收敛为「观察到 / 未观察到」：`true` 只在观察到本会话装配仍挂着官方 `@deepseek-ai/dsh-agent-instructions` 行时出现，`null` 表示尚未观察到。没有 `false` 的生产者——「官方未装配」是插件观察不到的否定事实，不能由「本会话有规则来源」反推。

当前全仓也没有 `true` 的生产者：pre-step 协调器的 `officialOwnerOf` 恒为 `undefined`，载荷因此恒为 `null`。据此清掉这条链上的内部死件：bridge 读协调器观察结果的类型与 JSDoc、指令快照契约里描述 `false` 的注释、契约测试里钉 `true/false/null` 的过时断言（改为钉当前语义）。载荷字段形状本轮不变。

## 取舍

留字段而删掉生产者读取口，等于「观察到官方装配」暂时没有出口：将来要上报必须显式重建这条链。收益是桥载荷对已部署的老客户端保持逐字不变，且不引入一个看似有用的 `false`——插件观察不到的否定事实一律不猜。

## 后续

第二步（不在本轮）：确认无客户端消费者后，先把桥载荷字段标记 deprecated，并在**下一个发版**删除；同一批清掉协调器上已无消费者的 `officialOwnerOf`。判定条件：字段在当前客户端只随草稿池携带、没有任何读取点，且发版说明写明字段移除。不在同一轮删字段——老客户端读不到字段会直接报错。
