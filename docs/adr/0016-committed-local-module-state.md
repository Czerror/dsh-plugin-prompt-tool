# 已安装模块从本地提交读取

状态：已采纳，2026-11-24。此决策替代 ADR-0008 关于完整定义提交、手改和恢复的部分。内存配装、独立正文版本和资源边界继续沿用。

## 背景

大型模块每次改一条规则都需要重新处理完整定义。旧格式同时用它安装、保存、恢复和导出。将已安装模块的持久状态按规则与共享输入分开，可以让一次保存只准备变更的对象，同时保留完整定义的交换能力。

## 决策

`module.yml` 用于安装、迁移、导入和导出。安装候选校验定义及资源后生成首个本地提交。提交记录引用模块清单、规则、共享状态和变量，以及必要的源级导出信息。清单保留声明键是否存在、显式顺序、未知输入和模块身份。

模块锁内先准备候选，再原子替换该模块的提交记录。规则正文、共享状态和变量保留独立版本检查。跨模块选择和排序仍逐模块提交。步骤固定已接受的运行快照，后续请求可采用新代。回执区分持久提交版本及各 Agent 生效版本，挂载失败按 Agent 保留上次有效贡献并允许重试同一代。存储损坏时读取可验证的上一代。没有可验证代时报告模块损坏并停止新请求贡献。

启动仅对支持的旧状态执行显式迁移。内置种子只补整个缺失目录。采用本地提交后，普通运行与桥接读取以该状态和登记资产为来源。导出从一个固定的已提交版本重组完整定义，保留支持的源级信息，分享包排除运行文件。跨越规则切片与其他输入边界的 YAML 别名若不能保留，候选校验拒绝该变更。

## 后果

原地编辑保留已提交的历史对象，便于并发读取和上一代恢复。显式覆盖安装成功后清理旧目录，删除模块时随目录回收全部对象。安装事务无法判定外部状态交接结果时保留备份供恢复。

作者通过工作台、模块工具或显式导入修改已安装模块。降级需先导出最新完整定义，再在隔离目录安装旧版。迁移前后的操作见[资产交换](../asset-transfer.md#升级与降级)。中断恢复针对提交记录切换前后和进程重启。操作系统崩溃或断电后的持久顺序需要单独的文件系统证据。
