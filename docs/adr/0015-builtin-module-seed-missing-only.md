# 内置模块只补缺失，不覆盖用户副本

状态：已采纳，2026-10-21。

随插件包分发的 `modules/` 是内置模块的**初始副本**，不是用户模块的同步源。启动时 `src/host/module-catalog.ts` 的 `ensureModuleSeed` 只对用户模块根中**缺失**的同名目录做补建（复制定义与资产，并从完整定义重建规则切片）；目标目录已存在（无论用户是否改过）一律跳过。是否补建只看目录存在性：不比较正文、不比较版本、不写差异；补建内部的定义或切片重建失败只跳过该模块，不写半成品。因此包内内置模块升级不会自动改写用户副本；用户删除某个内置模块后，下次启动会补回。要让某个内置模块长期不生效，应保留目录并改定义使其失效，而不是删目录。

取舍：放弃「升级时自动同步内置模块」的便利，换取用户自定义不被覆盖。显式导入仍走预览与确认，可由用户选择覆盖；那是用户发起的写入，不是启动补种。若将来要提供内置模块更新，必须显式、可选择，并且只写用户未修改的副本——不能把默认路径改成「有差异就覆盖」。

本决策补强 [ADR-0008](0008-module-slices-memory-assembly.md) 的完整定义所有权与目录交换边界，不改变 [ADR-0005](0005-preset-to-module.md) 的模块身份。回归测试须覆盖首次补建、二次幂等、删除后补回，以及用户改过的副本不被改写；`test/host/module-seed.test.mjs` 现已覆盖这四项。
