# 资产导入与模块导出

资产语义由 host 识别。页面选择来源、显示预览并提交用户决定。`module.yml` 用于交换完整定义，安装后的本地提交拥有模块清单与规则切片。角色卡导入为普通模块，模块记忆和工作区指令正文各有独立所有者。

## 输入与入口

已有模块从旧目录预览并补入私有数据，见[模块私有数据导入](subsystems/params-migration.md#模块私有数据预览与导入)。

模块页支持文件夹、ZIP、原生 JSON/YAML 定义，以及 ST 预设、PNG/JSON 角色卡和世界书。所有来源共用预览与安装链，角色卡不建立独立角色库或专属目录。

规则的 `templateFile` 应指向独立模板资产，例如 `./assets/prompt.txt`。导入、迁移和规则保存均拒绝引用模块根目录的 `module.yml`、`rules/` 或本地格式标记。若旧模块把交换定义用作模板，请将所需内容另存为资产，再重新导入。

单文件上传走 `/asset-upload`，只写当前 bridge 拥有的暂存来源；来源句柄有效期 15 分钟，每个 bridge 最多保留 4 份。取消、释放、卸载会回收来源；重启只回收带本插件标记且已过期的来源。

文件夹使用显式 `base64` 字节载荷。JSON bridge 保持 32 MiB 上限，原始来源和 ZIP 解压总量上限为 64 MiB、最多 2048 个条目；较大的文件夹请先压缩为 ZIP。路径、编码、字节上限与 PNG chunk／解压限制均在宿主复检。

文件夹和 ZIP 只剥离一层统一外壳。顶层唯一原生定义确定后，其余文件作为附件，不因附件包含 ST 顺序表而改变转换。无原生定义的多份 ST 来源按显式输入顺序合并，转换报告复用同一份 ID 映射。未知、矛盾或多定义输入拒绝，不能成功生成空配置。

## 预览与提交

预览显示来源类型、目标 ID／名称、文件数与字节、配置数、转换诊断及类型／顺序组候选。原生文件同样有资源摘要。默认同名另存，用户选择覆盖后须明确确认；改变来源、目标、名称、类型、组或覆盖模式都会使旧确认失效。

来源摘要和预览版本由服务端计算，绑定内容、选择与当前目标版本。提交必须回传两者；读取失败不能当成目标不存在。过期返回冲突，UI 保留来源并提供重新预览。

模块安装先在同文件系统暂存完整候选，校验定义、工具、模板和组合后生成首个本地提交。候选目录使用合法目标 id。安装事务在锁内复核目标版本并交换目录，冲突时保留旧目标，恢复失败时保留备份位置。内置模块只在整个用户模块目录缺失时补建。[ADR-0015](adr/0015-builtin-module-seed-missing-only.md)

内置同 ID 补建或新建以包内定义生成首个本地提交，`assets/` 仍留在包内。所有模块资产读取逐文件采用用户目录→包内同 ID 的顺序，空文件覆盖、错误拒绝。导入预览只读取上传文件与可信包内资产，确认版本包含包内资产摘要，包更新后需重新预览。显式上传文件按既有覆盖规则落盘，已有用户资产照常导出。

导入以包中的完整 `module.yml` 为准，夹带的 `rules/` 不参与物化。定义及 ZIP 导出从同一提交重组完整定义。预览只读，版本绑定提交与相关资产、分享投影。内容变化会使旧确认冲突，重新预览后再导出。

安装成功与列表刷新分开报告，刷新失败不自动重复安装。导入不自动切换当前编辑模块；用户可在结果页显式切换。

角色来源与 `module_import` 工具覆盖时保留 memory.md、未知用户资产与未替换头像；工作台 / bridge 的普通包覆盖只保留 `data/`（旧数据优先，包内同名文件只补缺失），其余以用户确认的完整候选为准。模块私有文件（memory.md、assets/、data/）只由 `module_file_read` 按需读取，不因导入或更新自动注入。

## 导出、复制与分享边界

“完整 ZIP”包含权威定义、预设正文、图片、自有组合和本地模块，附 `prompt-tool-package.json` 的格式版本、兼容要求与文件摘要。导入检查清单与实际条目一致；ZIP 的上跳、绝对路径、链接、特殊文件、大小写／规范化冲突、加密、损坏及解压超限均拒绝。

内置同 ID 的完整 ZIP 只携定义与实际用户覆盖，缺失的包内资产由接收端插件提供；包内模板满足依赖时不按缺附件拒绝。另存为不同 ID 时把来源内置资产补入候选，上传覆盖优先，之后独立维护。预览展示实际安装文件集合；普通自建模块的自有资产按原规则完整交换。

ZIP 排除本地提交及规则对象、旧投影目录、`memory.md`、`data/`、技能库、全局变量和工作区指令或策略。根 `agents.md` 是按现有规则处理的模块内容资产。

导入不安装引擎。组合通过插件包说明符引用共享引擎，由接收端已安装的插件提供；包内遗留 `engine/` 不参与运行，引擎版本随插件更新。

“仅定义 YAML”不携带附件，界面说明遗漏数量。完整导出检查显式本地模块与模板引用；缺失或根外资源阻止完整下载，定义模式仍说明限制。静态检查不能证明任意用户模块动态构造的路径完整，用户模块的运行前提仍需自行提供。

历史模块可能带自动同步的记忆规则及 meta.characterMemories 证明。分享出口继续在副本中排除可核验的历史自动记忆，不修改原模块；普通同名规则保留，无法确认的历史条目须明确选择。新记忆写入不再生成该类规则或登记，入站来源的生成证明不可信。

模块复制从当前本地提交生成新身份并保留本地素材，包含分享导出省略的私有内容。内置模块改名复制先补齐包内资产，再由用户资产覆盖。复制品按自己的完整 ID 独立维护。Web 和 CLI 共用当前 `.prompt-tool` 定位规则。

## 升级与降级

1. 升级前备份模块目录与所需私有数据。新版首次启动验证并物化使用旧格式的模块，包括尚未启用的模块。已有本地提交的目录继续从该状态读取。当前代损坏时可回到完整验证过的上一代。没有有效代时，按诊断从备份恢复或显式重新导入完整定义。
2. 降级前在新版工作台导出最新完整定义。有附件的模块用 ZIP 导出并解包，另备份所需的私有数据。旧版不理解本地提交，原目录里的旧 `module.yml` 可能过期。
3. 用独立 `DSH_HOME` 和全新的模块目录运行旧版。将导出的 `module.yml` 及附件装到对应 ID 的目录，按需单独恢复兼容的私有数据和启用设置。新版的版本化目录保留作备份。
4. 返回新版时，若要采纳旧版编辑，先从旧版取得最新完整定义，再在新版显式导入，或让独立旧格式副本在新版启动时迁移。使用导入覆盖时先核对目标、完整定义和资产预览。

工作台与公开 API（`exportModulePackage` / `expandModuleSource`）的 ZIP、仅定义 YAML 与文件夹出口共用资源清单和分享规则。省略目标时下载为 `<id>.zip`，已存在目标拒绝覆盖。

## 模块归属

| 文件 | 责任 |
|---|---|
| `shared/asset-transfer.ts`、`bridge-contract.ts` | 字节、选择、摘要与响应契约 |
| `host/import-source.ts`、`character-png.ts` | 内容判别、转换、来源报告、受限 PNG 解码 |
| `host/asset-sources.ts`、`asset-archive.ts`、`shared/asset-path.ts` | 生命周期暂存、ZIP 载体；相对路径边界校验由 shared 原语承载（ZIP/上传/模块包共用） |
| `host/module-package.ts` | 预览、严格候选、安装与导出 |
| `host/module-dirs.ts`、`module-catalog.ts`、`module-capabilities.ts`、`module-install.ts`、`write-module.ts`、`module-install-transaction.ts`、`module-write.ts`、`module-slices.ts` | 合法身份、根归属、复制、候选校验、安装事务、本地提交与完整定义重组 |
| `host/module-files.ts`、`host/legacy-export.ts` | 模块私有文件（memory.md、assets/、data/）；历史分享证明兼容 |
| `client/data/use-import-preview-flow.ts`、`ui/ImportDialog.tsx` | 读取到结果的统一生命周期与共享呈现 |

安全与文件行为通过公共接口验证；浏览器验收检查文件输入、确认、过期、取消、错误和键盘操作。验证环境隔离 cwd 与 DSH_HOME，不操作运行中服务。
